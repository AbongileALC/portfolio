# 1. Agile Team Charter

[← Back to home](index.md)

> **Note on this evidence:** My placement team did not use a formally signed charter. The charter below is **reconstructed from working practices that are visible in the team's Zoho Projects task records** (task comments, assignments and status changes). Each agreement shows where the evidence for it comes from.

## Team purpose

To configure, support and improve Zoho One systems for the firm and its clients, delivering working, tested solutions while keeping client and staff data secure.

## Team roles

| Role | Responsibility |
|---|---|
| Intern (me) | Build and configure fields, forms, layouts and flows; test; handle support tickets; log time and progress |
| Mentor / systems administrator | Assigns technical tasks, guides the intern, reviews and approves builds |
| Operations manager | Creates operational tasks, tests completed work and confirms closure |
| Senior consultant | Leads the client migration project and reports progress to the client |
| Training lead | Owns the online training platform and course testing |

## Working agreements

| # | Agreement | Evidence in task records |
|---|---|---|
| 1 | All work is tracked as a task in Zoho Projects with an owner, start date, due date and status | Every exported task has owner, dates and status |
| 2 | Time is logged against the task it was spent on | Mentor comments: *"Please log your time here"* (Field Build, People Field Build, course testing) |
| 3 | Supporting documents and screenshots are attached to the task | Mentor asked for the working document in the task's documents tab and for screenshots |
| 4 | Feedback and hand-overs happen through @mentions in task comments | Comments request feedback from named owners before go-live |
| 5 | The person who requested the work tests it before it is closed | Vendor contact section: built → "please retest" → requester confirmed → closed |
| 6 | Changes are made in the **sandbox first**, then in production only after client sign-off | Users and security task: changes prepared in sandbox, held for client approval |
| 7 | Changes are recorded in a change log / open items log with an undo file | Users and security task comments |
| 8 | Support requests go through Zoho Desk tickets | Weekly reports Weeks 1–3 |
| 9 | Interns submit a weekly progress report | Intern Progress Form, Weeks 1–11 |

## Core values (shown through the agreements)

- **Transparency** – progress, blockers and decisions are written in task comments where everyone can see them.
- **Accountability** – every task has a named owner and logged time.
- **Quality** – work is tested by someone other than the builder before closure.
- **Security and confidentiality** – sandbox-first changes, least-privilege access, POPIA compliance.

## Boundaries

- Interns work with intern-level access; when a task needs admin rights, the intern raises it in the task comments and waits for access rather than working around it.
- No changes to client production systems without sign-off.
- Client and staff data stays inside company systems.
